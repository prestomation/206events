## Source discovery: implementing an existing candidate

No open source-discovery PR to sweep (`search_pull_requests` for
source-discovery naming in this repo: the 4 open PRs are a proxy-staging
PR for `puget-soundkeeper`, an unrelated web fix, a proxy-staging PR for
`seattle-food-trucks`, and a long-stale single-source PR for
`8bit-brass-band` — none touch the drain caches or candidate files).

Re-checked the existing `status: candidate`/`investigating` "200 + 0
events" pool first (Phinney Books, Nudibranch Coffee, CoCA Seattle,
Westland Distillery, Seattle Cider Taproom, Seattle Mahjong Club, The
Growler Guys): all still at 0 upcoming events, no change.

Searched music venues, bookstores, comedy, breweries/distilleries
(Georgetown), record stores, climbing gyms, maker spaces, night
markets, queer nightlife, walking/running/cycling clubs, Beacon
Hill/Rainier Valley community orgs, and fresh "new venue opened"
roundups — a near-total remine of verticals already covered, reflecting
how thoroughly this repo's `docs/source-candidates/` (1000+ files) has
been worked. Notable near-misses, not implemented this cycle:
- **Sake Noire** (Hillman City sake/jazz bar, opened Jul 2026) —
  Squarespace confirmed, two candidate collections
  (`/jazz-industry-events`, `/sake-events`) both at 0 upcoming events
  (the latter is actually a blog-style recap of past pop-ups, not an
  events collection); `/tickets-events` is a 1-item Squarespace
  commerce product, not an events feed. Monthly jazz series confirmed
  via press but with no fixed day-of-week, so not recurring-YAML
  material either. New candidate file:
  `docs/source-candidates/sake-noire.md`.
- **Cyclists of Greater Seattle (COGS)** — re-evaluated its existing
  `notviable` verdict (from 2026-07-05, pre-King-County-rule) since most
  of its ride locations (Kirkland, Snoqualmie Falls) are in King County
  now. Confirmed the WildApricot RSS feed (`/events/RSS`) still works,
  but only 1 truly upcoming event is in it (an Annual Member Meeting at
  Ivar's Salmon House, Seattle) — too thin to justify a custom
  RSS-parsing ripper (no built-in RSS-ingest type exists) this cycle.
  Left `status: notviable`, noted the re-check.
- **PublicDisplay.ART aggregator mining** — followed up on orgs listed
  in the citywide aggregator (already home to `art_love_salon` and
  `occidental_fine_arts_center`) that lack their own dedicated source.
  Arts Impact (2 single-day events) and Earth Creative (2) both have
  real `hours` data on their event detail pages, but both events'
  `location` field reads `"pda_office"` rather than the org's own
  address — ambiguous (literally "PublicDisplay.ART's own office"?),
  so not confidently attributable to a street address. Wa Na Wari (org
  id 158, already `notviable` on its own site) only has multi-week
  exhibition-range entries in the aggregator, no single-day events.
  None implemented.
- **Seattle Eagle** (Capitol Hill leather bar) — `seattleeagle.com`
  connection-reset from this environment on every attempt; blocked, not
  stageable (nothing to prove from here).

**Implemented:** Discover Burien (`discoverburien.org`), a
`status: investigating` candidate stuck since 2026-09-24 because its
Squarespace `calendarView` collection mixes past/future dates in
`items` and a `month=` crawl to page forward triggers a bot challenge.
Found that no crawl is needed — the unparameterized `?format=json`
request already spans into the next month — and the real gap was that
`lib/config/squarespace.ts`'s `items` fallback (for non-`upcoming`/
`past` collections) didn't filter by date the way the adjacent `past`
fallback does. Fixed the shared helper (untested fallback, no other
live source depends on it) and added `sources/discover_burien/`.
Verified 16 future events, 0 errors via `ONLY_SOURCE=discover-burien`.
