Walk / belltownartwalk.com) initially looked like new 🔥 high-confidence
candidates — both self-guided monthly walks with a fixed day/time — but
turned out to be **false positives**: a code-review pass caught that
`sources/recurring/west-seattle-artwalk.yaml` and
`sources/recurring/belltown-artwalk.yaml` already exist and are live
(`status: added` in effect, same URLs, same 2nd Thursday / 2nd Friday
schedules). I had checked `docs/source-candidates/` for an existing
per-candidate file (there wasn't one for either — they predate that
directory's per-file tracking convention) but skipped the step-4 check
of `sources/` itself, so I drafted duplicate candidate docs for
already-implemented sources. No candidate files were kept for these; the
existing YAML rippers remain the record. Lesson for next cycle: always
check `sources/recurring/` directly by slug, not just
`docs/source-candidates/`, before writing up a "new" recurring-event
lead — a Google-able art walk with a well-established web presence is
exactly the kind of thing likely to have been added early, before
per-candidate docs existed.
