## Source discovery: implementing existing candidate (dance)

Picked the highest-confidence unimplemented 💡 candidate from
`docs/source-candidates/` rather than running fresh searches this cycle:
**NW Dance** (`nwdance.net`), previously investigated 2026-08-14 as a
"Modern Events Calendar Lite" WordPress site with good event volume across
several Ballard-area halls, flagged to check for an ICS export before
resorting to HTML scraping.

No Tribe-Events-style `?ical=1`/`?mec-ical-export=1` endpoint exists for MEC,
but WordPress auto-registers a native RSS feed at `/events/feed/`, and MEC
extends it with structured `mec:startDate`/`mec:startHour`/`mec:endDate`/
`mec:endHour`/`mec:location`/`mec:cost` fields per item — no HTML scraping
needed after all. Implemented a custom `IRipper`
(`sources/nw_dance/ripper.ts`) that parses the feed directly. The feed's
`mec:location` is a bare venue name with no address, so the ripper maps the
two venues seen so far (Leif Erikson Hall, Sunset Hill Community Hall) to
full street addresses for precise geocoding, falling back to the bare venue
name for the geocoder to resolve on its own if a new venue appears.

Verified live via `ONLY_SOURCE=nw-dance npm run generate-calendars`: 10
events, 0 parse errors, 0 unresolvable geocodes.
